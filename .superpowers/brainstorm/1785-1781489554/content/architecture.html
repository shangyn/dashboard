系统架构设计

数据库 · API · 前端路由 — 三张图看清整体结构

📦 数据库设计（SQLite — 3张表）

👤 user 用户表
idInteger PK
usernameString(80) UNIQUE — 工号
passwordString(200) — bcrypt哈希
real_nameString(50) — 真实姓名
role_idFK → role.id
is_activeBoolean, 默认True
created_atDateTime, 默认now
🔒 role 角色表
idInteger PK
role_nameString(50) UNIQUE
permissionsText — JSON数组
created_atDateTime
permissions 示例：
["dashboard", "user_manage", "role_manage", "module_manage"] — 管理员
["dashboard_receivables"] — 报价员
📊 module 模块表
idInteger PK
nameString(100) — 看板名称
descriptionText — 描述
permissionString(50) — 对应权限标识
urlString(200) — dashboard路径
iconString(50) — 可选图标
sort_orderInteger — 排序
is_activeBoolean — 启用/禁用

🔌 后端 API 一览（前缀 /api，JWT 认证）

模块方法路径说明权限
认证POST/api/login工号+密码 → 返回JWT+用户信息无
GET/api/current-user返回当前登录用户信息登录即可
用户管理GET/api/users分页查询用户列表user_manage
POST/api/users新增用户user_manage
PUT/api/users/<id>修改用户信息user_manage
DELETE/api/users/<id>删除用户user_manage
PUT/api/users/<id>/reset-password重置密码为123456user_manage
角色管理GET/api/roles查询所有角色role_manage
POST/api/roles新增角色role_manage
PUT/api/roles/<id>修改角色（含权限）role_manage
DELETE/api/roles/<id>删除角色（有关联用户则禁止）role_manage
模块管理GET/api/modules查询所有模块module_manage
POST/api/modules新增模块module_manage
PUT/api/modules/<id>修改模块module_manage
DELETE/api/modules/<id>删除模块module_manage
权限GET/api/my-modules当前用户可见的模块列表登录即可

🧭 前端路由设计

管理员路由（有侧边栏）
/login — 登录页
Layout（侧边栏 + 顶栏）
├ /dashboard — 首页
├ /user-manage — 用户管理
├ /role-manage — 角色管理
└ /module-manage — 模块管理
普通用户路由（无侧边栏）
/login — 登录页
Layout（仅顶栏）
├ /home — 模块卡片选择页
└ /dashboard/:id — iframe看板页

🔄 核心流程

1 登录 → 后端验证工号+密码 → 返回 JWT token + 用户信息（含角色和权限列表）
2 前端判断 → 用户的 role 名称是否为 "管理员"？
✅ 是管理员 → 进入 AdminLayout（侧边栏 + 顶栏），路由到 /dashboard
❌ 非管理员 → 进入 UserLayout（仅顶栏），路由到 /home 看板选择页
3 /home 页面 → 调用 /api/my-modules → 根据用户权限过滤 → 展示模块卡片网格（3列）
4 点击卡片 → 跳转 /dashboard/:id → iframe 加载 Flask 托管的 dashboard 页面
