## 4. 本轮发现并修复的产品缺陷

### 4.1 管理员解锁弹窗类型未重置（ADM-09）

- 现象：先选「作废实发」并取消，再次打开仍停留在「作废实发」。
- 修复：`openUnlockDialog` 每次打开都把类型重置为「撤回周计划」。
- 复测：ADM-09 通过。

### 4.2 每日实发页继承全量页隐藏筛选（DAY-14）

- 现象：在全量页设置「发货状态」后切到每日实发，列表和导出仍被该隐藏条件限制。
- 修复：切换到「每日实发」时清空 `statuses`、`booking_status`、`expectedRange` 并重新加载。
- 复测：DAY-14 通过。

### 4.3 未实发梯号执行「作废实发」仍有副作用（X-05、X-06、API-36）

- 现象：没有有效实发记录时仍清空 `actual_ship_date`、写入 `shipped_voided` 标记，并提示「已处理 0 条」。
- 修复：后端 `unlock(shipment)` 无有效实发时计入 `skipped` 并直接跳过，不写标记、不清日期；前端按类型显示「无有效实发记录，未改动」。
- 复测：X-05、X-06、API-36 通过。

### 4.4 并发提交同一梯号产生重复有效实发（API-31）

- 现象：两个并发请求同时通过「是否存在有效实发」检查，均返回 200，库中出现 2 条 `is_void=0` 记录。
- 修复：
  1. 启动时为 `st_daily_shipment(ladder_key) WHERE is_void=0` 创建部分唯一索引 `uq_st_daily_shipment_active`；
  2. `record_daily_shipments` 捕获 `IntegrityError`，回滚并返回「该梯号已有有效实发记录，可能由并发提交产生，请刷新后重试」。
- 复测：API-31 通过，状态码为 `[200, 400]`，有效记录数为 1。

## 5. 测试脚本修正（非产品缺陷）

以下失败均确认为测试脚本定位/等待问题，不是产品缺陷：

- 导入页签等待了不存在的 `.st-table` 选择器；
- 清理预览的旧提示被误读为同步结果；
- 草稿日期读到勾选框 `on`，未定位到日期输入框；
- 错误密码/历史补录/计划外实发读取到旧提示；
- 响应式检查使用了浏览器不支持的 `:visible` CSS 选择器；
- 状态筛选输入框应点击 Element Plus 的 `.el-select` 容器。

## 6. 观察项与上线风险

### 6.1 每日数据更新机制

代码中**没有发现** APScheduler、Celery 或 cron 独立每日定时任务。当前同步触发点为：

1. 管理员在「导入管理」点击「立即同步」；
2. 合同台账上传成功后的自动同步；
3. 月度计划导入提交后的同步；
4. 从单月填报生成计划提交后的同步。

如果生产环境每天不会上传合同台账、也没有人点击「立即同步」，排产完工日期、整梯发货日期和回款比例不会自动刷新。上线前需确认日常台账上传流程，或另行增加每日定时任务。

### 6.2 已发货梯号在业务填报页消失

每日实发后，该梯号会从业务填报页的「我已提交 / 待发货」区域消失，管理员全量页仍可见。该行为符合「待发货」语义，但需业务确认是否希望填报人继续看到已发货记录。

### 6.3 SQLite 并发与部署

本次已用数据库唯一索引兜底重复实发，但 SQLite 在高并发写入下仍可能出现 `database is locked`。生产建议评估 WAL 模式和 worker 数量；至少保留 `busy_timeout`。
