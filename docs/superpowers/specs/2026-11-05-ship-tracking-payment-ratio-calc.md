# 发货梯号明细 - 未满 100% 回款比例计算（2026-11-05）

## 目标与范围

- 只在「发货梯号明细」模块内，把台账 BN 列小于 1 的梯号，按回款台账重新计算后写回
  `st_tracking_item.payment_ratio`。
- 不新增页面列、不新增导出列；页面和导出继续使用现有「回款比例」列与「100% / 其他」筛选。
- 不修改 `cc_ledger_contract`、其他 `cc_*` / `mf_*` 表，不影响其他模块。
- 新增内部计算记录表（`st_payment_file`、`st_payment_calc_run`、`st_payment_calc_detail`）用于上传状态、
  计算审计、异常清单和回退；这些表不作为页面列展示。

- 表 B 读 2024/2025/2026 三个 sheet；表 R 读 2025/2026 两个 sheet；表 E 只取「款项类型 = 抵佣金」。
- 所有文件路径通过上传目录配置，不写死本机 `E:\System\数据源`，正式服务器可直接使用。

## 目标梯号

- 遍历 `st_tracking_item` 中当前有效的发货梯号。
- 以 `cc_ledger_contract.payment_ratio`（台账 BN）为准：
  - `>= 1`：保持 100%，不重算。
  - `< 1` 或为空：进入计算。
- 台账找不到该梯号、合同额无效等无法计算的情况：保留原台账比例，并写入异常清单。

## 分摊规则

1. 指定了梯号的回款（外币表 B 的梯号列、抵佣金表 E 的标的编号、人民币表 R 的回款性质）：
   - 直接落到对应梯号。
   - 同一行有多个梯号时，按这些梯号的合同额（人民币）比例分摊。
   - 指定的梯号在台账中不存在时，记录异常；若一个都不存在，转入该合同的合同池。
2. 没有指定梯号、只有合同号的回款：进入合同池。
3. 合同池按该合同下全部梯号的合同额（人民币）比例分摊；不是平均分。
4. 分摊金额保留 2 位小数，尾差按最大余数补到梯号，保证分出去的总金额不丢。
5. 若合同内部分梯号合同额为 0：只在实际合同额大于 0 的梯号之间分摊；全部为 0 时才平均分。
6. 指定梯号组内部分梯号合同额为 0：同样只在有合同额的梯号之间分摊，0 合同额梯号分 0。

## 特殊规则：先回满再分配

人民币表 R 的 `回款性质` 支持类似：

`4#-7#回满，剩余放1#-3#`

处理口径：

1. 先把本行金额优先分配给 `4#-7#`，使这些梯号的累计回款达到合同额 100%。
2. 补满后仍有剩余，剩余金额按合同额比例分配给 `1#-3#`。
3. 如果本行金额不足以补满 `4#-7#`，则在 `4#-7#` 内按合同额比例分摊；不把不足额部分转给 `1#-3#`。
4. 「累计回款」指本次计算中、在本行之前已处理的指定梯号回款（含外币/抵佣金折算人民币）；不直接采用台账 BN 作为已回款。
5. 合同池回款在指定梯号回款之后处理，不参与「回满」的已回款基数。
6. 如果 `4#-7#` 和 `1#-3#` 都已满，剩余金额仍按合同额比例分给 `1#-3#`；单个梯号超过 100% 时页面统一显示 100.00%，审计明细保留原始计算比例，不做二次转移。

## 备注与特殊值

- 合同号为 `见拆分`：跳过该行。
- 备注包含 `原 X 后调至 Y`：继续整行跳过（按确认口径）。
- 备注包含 `折合 X 美元/欧元/澳元...` 或 `折合美元 X`：按折合后的币种和金额记录；多段折合加总。
- 有折合备注时，不再额外加手续费（包括备注中写明的 `+159手续费`，按确认口径不加）。
- 没有折合备注时，回款金额 = 金额 + 手续费。
- 外币表 B 的梯号列若包含 DHT/DYT 合同号，合同号以该合同号为准。
- 人民币表 R 的 `回款性质` 若包含 DHT/DYT 合同号，合同号以该合同号为准。

## 比例计算

- 单币种且回款币种等于该梯合同币种，且合同额（原币）有效：
  `比例 = 已回款原币 / 合同额（原币）`
- 同一梯号出现多币种，或币种不一致：
  - 统一折人民币；
  - `比例 = 已回款人民币 / 合同额（人民币）`；
  - 汇率优先用台账该梯汇率，缺失时用汇率对应 txt；
  - 人民币汇率按 1。
- 币种为空时，若能确定该梯合同币种，按该梯合同币种处理；否则按人民币路径并记录异常。
- 结果小于 0 按 0；大于等于 1 页面统一显示 100.00%，原始计算值保留在审计明细中。
- 页面显示保留 2 位小数；筛选「100%」按原始值 >= 1 判断。

## 找不到回款记录

- 台账 BN > 0 且本次没有任何回款记录：保留台账 BN，状态记为 `no_payment_keep_ledger`，进入异常清单。
- 台账 BN = 0 且没有回款记录：写 0%，状态记为 `no_payment_zero`。
- 不因为缺少某张回款表而把全部梯号清零；文件缺失时整次计算不执行。

## 触发方式

- 主页面所有能看到「发货梯号明细」的角色都可以上传四张回款文件和点击「计算回款」。
- 计算以按钮为主：点击后后台执行，页面轮询状态，显示计算中/成功/失败。
- 台账每天上传/同步成功后，自动触发一次后台重算；若已有计算在运行则跳过。
- 台账同步会先把明细回款比例写回台账 BN，因此自动重算不做「刚算过就跳过」的时间去重，避免同步后停留在台账原值。
- 上传回款文件本身不自动计算；由用户点击按钮或等待下一次台账自动重算。
- 计算使用文件锁，禁止并发重复计算；失败整次回滚，不写半成品。

## 写回与导出

- 只写 `st_tracking_item.payment_ratio`。
- 主明细 Excel 继续使用现有回款比例列，不新增列。
- 另提供「回款计算审计」下载：计算汇总、梯号结果、分摊明细、异常清单。
- 执行「台账字段同步」时会先把回款比例写回台账 BN 原值；若四类文件齐全，随后会自动重算并覆盖为计算结果。
