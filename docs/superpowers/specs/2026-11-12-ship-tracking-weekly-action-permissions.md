# 发货梯号明细 - 改期与撤回动作权限（2026-11-12）

## 决策

- 提交周不再作为改期或撤回的业务门禁；`committed_on_week_start` 仅保留审计和统计用途。
- 改期使用独立权限 `ship_tracking_weekly_adjust`。
- 撤回使用独立权限 `ship_tracking_weekly_withdraw`。
- 首次迁移自动给现有业务填报角色授予改期权限；撤回权限不自动授予。
- 管理员（`is_admin` 或 `ship_tracking_admin`）具备两个动作的能力；实际周填报接口仍按模块归属校验。

## 判定规则

- 改期：已提交、未发货、计划有效，且新日期在当前填报窗口内。
- 撤回：已提交、未发货、计划有效。
- 权限只决定“能否做该动作”，记录状态决定“这条记录现在能否操作”。
- 后端是最终校验方；前端只根据接口返回的 `can_adjust`、`can_withdraw` 和阻塞原因渲染。

## 迁移

- 新增 `st_setting` 表保存模块级标记。
- `weekly_action_permissions_v1` 标记一次性授权已完成，避免管理员后续取消改期权限后被重启重新加回。

## 角色与发布

- 不新增角色，继续使用现有的「单月签排发填报」角色。
- 角色编辑页展示两个权限项只是配置入口；未勾选并保存时不会生效。当前只有该业务角色默认获得改期权限，撤回权限不默认授予。
- 代码发布后必须重新执行前端构建（`cd frontend && npm.cmd run build`），并重启后端。只回退源码而不更新 `dist`，服务器仍会继续提供旧页面。
- 构建后请对页面做强制刷新（Ctrl+F5）或清理浏览器缓存，避免 Chrome/Edge 继续加载旧的前端包。备注弹窗和日期选择器均使用 Element Plus 组件，不依赖浏览器弹出窗口权限。

## 验证

- 只有改期权限：可以改期，不显示撤回。
- 同时有改期和撤回权限：两个动作都可用。
- 只有撤回权限：只显示撤回。
- 无动作权限：显示不可操作原因。
- 已发货、未提交或计划已移除：两个动作都不可用。
