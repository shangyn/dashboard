# 发货梯号追踪 — 完整测试方案

> 版本：2026-11-03  
> 适用代码：`backend/ship_tracking`、`frontend/src/views/ship_tracking`  
> 目标：在上线前把所有页面、按钮、接口、导入流程、权限和数据口径逐项跑通；每个缺陷都要有复现步骤和回归用例。  
> 原则：先测后改。测试过程中发现的每个问题先记录，不在测试中途临时改代码，避免一边改一边引入新问题。

> 2026-11-05 补充变更：导入管理对所有可查看全量明细的角色开放；原「待安排」统一改名为「未提交待发货」。下文涉及这两个旧口径的预期以本补充为准。

## 1. 测试范围

### 1.1 包含

- 登录、菜单、角色权限、页面入口。
- 全量追踪：筛选、汇总、表格、固定列、横向/纵向滚动、分页、选择、历史、导出。
- 每日实发：批量实发、计划外实发、管理员解锁、日期校验。
- 导入管理：计划 Excel 预览/提交、订舱报表预览/提交、批次列表、异常列表、模板下载。
- 业务周填报：候选池、批量日期、逐行日期、草稿、提交、改期、撤回、已提交区。
- 后端接口：鉴权、参数校验、分页、导出、版本化、数据保留、审计日志。
- 兼容性：1920×1080、1600×900、1366×768，浏览器 100% / 125% 缩放。
- 已知缺陷回归：ST-PENDING-01 至 ST-PENDING-09。

### 1.2 不包含

- 回款相关字段和上传（本期明确不做）。
- 单月签排发填报模块本身的业务逻辑，只测试它与发货追踪的模块归属联动。
- 订舱源系统、物流系统的外部数据准确性。
