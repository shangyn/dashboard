## MF-ISS-01 提交后再保存草稿，数据已改但状态/版本/提交时间不变

- **级别**：P1
- **现象**：提交生成 v1 后，页面仍可编辑并点「保存草稿」。保存成功，业务数据（如签单台数）已变为新值；但状态仍为「已提交」，`submitted_at` 与版本号不变，`mf_submission` 未生成新快照。
- **复现**：
  1. `QA-FILL-ONE` 保存并提交（版本 v1）；
  2. `PUT /api/monthly-forecast/entry` 把 `sign_units` 改为 99；
  3. `GET /api/monthly-forecast/entry`：`sign_units=99`，`status=submitted`，版本仍为 1。
- **预期**：二选一——提交后锁定禁止编辑；或保存后状态回「草稿/已修改」，并提醒需重新提交。
- **实际**：页面显示「已提交」，数据与快照不一致；下游从单月生成仍读 v1。
- **代码**：`backend/monthly_forecast/services.py:375-463`（save_draft 不碰状态），`:466-509`（仅 submit 改状态/版本）。
- **建议**：增加 `dirty` 标记或对比最新快照；保存后若与最新提交快照不同，状态回退为「已修改」；提交后置灰保存按钮需产品确认。

## MF-ISS-02 无撤回/回退，历史版本接口无 UI 入口

- **级别**：P1（功能缺口）
- **现象**：提交后没有「撤回」按钮或接口；`GET /api/monthly-forecast/submissions` 可返回 v1/v2，但前端从未调用，历史版本不可见。
- **复现**：MF-11 接口返回两个版本；`MonthlyForecast.vue` 检索无 `submissions` 调用；MF-12 代码检索无 withdraw 路由。
- **预期**：提供撤回提交或至少历史版本查看；撤回后回到草稿并清理下游引用。
- **实际**：只能重复提交覆盖，旧版本静默堆积。
- **代码**：`backend/monthly_forecast/blueprint.py`（无撤回路由）；`frontend/src/views/MonthlyForecast.vue`。
- **建议**：先做「版本历史只读抽屉」，再评估是否允许撤回（需定义发货明细已生成时的回滚策略）。

## ST-ISS-01 周填报草稿被显示为「已提交待发货」

- **级别**：P1
- **现象**：周填报只点「保存草稿」，尚未提交，但全量页状态变为「已提交待发货」，汇总卡片计入已提交；业务方会误以为计划已提交。
- **复现**：SI-31 保存草稿 → SI-05 查询全量：`commit_status` 为空但 `expected_ship_date` 有值，状态推导命中 `committed`。
- **预期**：草稿显示「草稿/待提交」，仅真正提交后才进入已提交待发货。
- **实际**：草稿与提交在展示层无法区分。
- **代码**：`backend/ship_tracking/services.py:559-570`（save_weekly_draft 写 expected）；状态推导 `:254-268`。
- **建议**：状态推导优先识别 `draft_expected_ship_date` 且无 `committed_on`；或草稿不写 `expected_ship_date`，仅提交时写入（需评估全量页其他依赖）。

## ST-ISS-02 管理员解锁 weekly 不清草稿日期，业务撤回会清

- **级别**：P1
- **现象**：同一条已提交记录，业务人员撤回会清空 `draft_*`；管理员用「解锁」后 `draft_expected_ship_date` 残留，候选池/全量页可能带出旧草稿日期。
- **复现**：SI-35 撤回后 draft 字段为空；SI-37-DRAFT 管理员 unlock 后 draft 字段仍在。
- **预期**：两种回退路径结果一致（都清空草稿），或明确解锁只清承诺不清草稿的产品语义。
- **实际**：两条路径不一致。
- **代码**：`services.py:603-628`（withdraw 清 draft）对比 `:684-732`（unlock weekly 不清）。
- **建议**：unlock weekly 同步清空 `draft_expected_ship_date`、`draft_updated_at/by`；若需保留，UI 明示。

## ST-ISS-03 跨周改期/撤回与解锁的权限口径不一致

- **级别**：P1
- **现象**：跨周改期/撤回用 `role.is_admin` 判定；管理员「解锁」用 `ship_tracking_admin` 权限判定。自定义角色（仅 `ship_tracking_admin`）可以解锁，却被拒绝撤回/改期。
- **复现**：QA-SHIP-ADMIN-SCOPED 对跨周记录调用 withdraw → 400；同一账号调用 unlock → 200。
- **预期**：同一业务动作使用统一权限口径。
- **实际**：能力割裂，用户需先解锁再操作，但界面未提示。
- **代码**：`services.py:603-683`（is_admin）vs `:684-732`（can_admin）。
- **建议**：统一为 `can_admin`，或在跨周校验中允许 `ship_tracking_admin` 直接操作并记录审计。

## PERM-ISS-01 有模块归属的查看/实发账号被静默降级

- **级别**：P1
- **现象**：给「查看上传」或「发货梯号实发」账号配置模块归属后，进入发货模块直接落到填报页：全量明细、每日实发页签消失，无任何提示；管理员即使有归属仍进入全量页。
- **复现**：P-05 查看上传+归属 → scoped 填报；P-08 实发+归属 → 每日实发不可用；P-02 管理员+归属 → 仍全量。
- **预期**：角色能力优先或至少提示「因配置归属已切换为填报视图」。
- **实际**：能力被静默剥夺，用户无法自查。
- **代码**：`services.py:103-158`（can_full_view / can_daily_edit）、`:203-237`（build_context）。
- **建议**：明确规则——查看类角色不受归属影响，或归属只限制数据范围而非页面；必要时在 context 返回降级原因并在前端提示。

## PERM-ISS-02 只有表头的名单文件会清空全部归属

- **级别**：P1（高危操作）
- **现象**：上传一个只有表头、无数据行的名单文件，接口返回成功并 `UserScope.query.delete()`，所有模块归属被清空，随后所有填报人员失去模块。
- **复现**：MF-33 构造仅表头文件 → HTTP 200、`rows=0`，`mf_user_scope` 由 N 变 0；MF-33-RESTORE 从快照恢复。
- **预期**：无有效数据行时拒绝导入并保留原归属；全量替换前需二次确认/自动备份。
- **实际**：先删后插，没有事务保护。
- **代码**：`backend/monthly_forecast/handlers.py:117-141`。
- **建议**：`len(table) <= 1` 直接返回失败；解析全部成功后再在事务内替换；导入前写入快照表或返回可回滚 token。

## UI-ISS-01 名单导入失败仍弹绿色成功提示

- **级别**：P2
- **现象**：文件为空、表头不符等失败场景，接口返回 `{success:false, message:...}`，前端仍 `ElMessage.success` 展示该 message。
- **复现**：MF-32 源码确认 `handleImportScope` 固定成功提示。
- **预期**：按 `data.success` 选择 success/error 提示。
- **代码**：`frontend/src/views/MonthlyForecast.vue` `handleImportScope`。
- **建议**：`data.success === false` 时 `ElMessage.error`，并展示 `rows/原因`。

## UI-ISS-02 有归属管理员「名单管理」按钮可见但抽屉不渲染

- **级别**：P2
- **现象**：管理员有模块归属时进入填报模式，顶部仍有「名单管理」按钮；点击后 `scopeVisible=true`，但 `ScopeManageDrawer` 只写在只读 `v-else` 分支，页面无反应。
- **复现**：MF-30 断言按钮由 `context.can_import_scope` 控制，抽屉位于只读分支（索引 11268 vs 1336）。
- **预期**：按钮与抽屉同层，任何模式点击都能打开。
- **代码**：`MonthlyForecast.vue:33-35`、`:210`、`:240`。
- **建议**：把 `<ScopeManageDrawer>` 移到两个分支之外，或按钮仅在只读模式显示。

## UX-ISS-01 移除自己最后一条归属后仍在填报模式，下次保存 403

- **级别**：P2
- **现象**：填报人员在名单管理中移除自己的最后一条归属，当前页仍显示填报模式；再次保存返回 403，页面无自动刷新/跳转。
- **复现**：MF-34 移除后保存 403。
- **预期**：移除后立即刷新 context，切换为无权限/只读提示。
- **代码**：`MonthlyForecast.vue` 名单操作成功后未刷新 context。
- **建议**：名单变更后重新拉取 context，必要时 `router.replace` 或展示空态。

## DATA-ISS-01 导出预计发货明细按字符串排序

- **级别**：P2
- **现象**：导出明细按 `module_name, ladder_no` 字符串排序，同合同出现 `1#, 10#, 11#, 2#`；候选池用自然序，两个入口顺序不一致。
- **复现**：`export_shipping` 查询 `order_by(ShipSelection.module_name, ShipSelection.ladder_no)`。
- **预期**：与候选池一致的自然序。
- **代码**：`backend/monthly_forecast/services.py:644-681`。
- **建议**：查询后按 `_ladder_natural_key` 排序，或 SQL 中拆分数字段。

## UI-ISS-03 关键字筛选只重置候选页码，已提交区可能停在空页

- **级别**：P2
- **现象**：周填报关键字同时过滤候选池和已提交区；`watch(keyword)` 只重置 `candidatePage`，已提交区页码不重置。筛选后结果不足当前页时，已提交区显示空页。
- **复现**：`WeeklyFill.vue:441-442` 只重置候选页；`:305` 已提交列表同样受 keyword 过滤。
- **预期**：关键字变化时两个分页都回到第 1 页。
- **建议**：watch 中同时 `submittedPage.value = 1`。

## FEAT-ISS-01 计划批次无回滚/撤销入口

- **级别**：P2（功能缺口）
- **现象**：计划导入生成新版本后，没有回滚到上一版本的 API 或按钮；旧批次仅被标记 `superseded`，快照保留但没有恢复入口。
- **复现**：SI-21 只验证版本 +1、旧批次 superseded、快照保留；`ship_tracking/blueprint.py` 无 rollback 路由。
- **预期**：产品确认是否需要「回滚到上一版本」及对已产生实发/订舱的影响。
- **建议**：若需要，按 `st_plan_item` 快照反向恢复并记录审计；否则在文档中明确不支持。

## UI-ISS-04 取消「全选本页」会删除同梯号的手工选择

- **级别**：P3
- **现象**：用户先手工添加某梯号（`is_manual=true`），该梯号又出现在候选当前页；取消「全选本页」时 `delete next[row.ladder_no]` 会把手工会员一并删除，来源标记丢失。
- **复现**：`MonthlyForecast.vue:370-383` 取消分支未区分 `is_manual`。
- **预期**：取消全选只移除候选勾选，不删手工行。
- **建议**：取消分支跳过 `next[row.ladder_no]?.is_manual`，并补单测。
