# 单月签排发填报 —— 模块名单管理 操作明细

适用范围：单月签排发填报页面（/monthly-forecast）右上角的「名单管理」抽屉。
本文只讲"点哪里、会发生什么"，不讲技术实现。

---

## 一、先搞清三个概念

| 名词 | 通俗解释 | 存在哪里 |
|------|----------|----------|
| 账号 | 登录平台用的工号（DT号） | 用户管理里的账号 |
| 模块 | 业务口径的模块名，比如「埃塞-1」「改造」 | 系统里所有出现过的模块名 |
| 归属 | 「某个账号可以填报某个模块」这一条关系 | 名单管理这张表（一行 = 一条归属） |

一个账号可以有 0 条、1 条或多条归属：

- 0 条归属 → 登录后是**只读汇总**：能看全部模块的汇总、能导出「预计签排发」，
  但不能填报、不能导出「预计发货明细」。
- 1 条归属 → 只能填报那一个模块。
- 多条归属 → 顶部会出现模块下拉，可以切换着分别填报。

---

## 二、从哪里进入

1. 打开「单月签排发填报」页面。
2. 右上角点「名单管理」，右侧弹出抽屉，标题就是「模块名单管理」。
3. 抽屉里从上到下依次是：
   - 标题栏：`模块名单管理` + 「新增」按钮
   - 工具行：模块筛选下拉、关键词输入框（DT号/姓名）、「只看异常」勾选框、「刷新」按钮、`已显示 / 全部 条` 计数
   - 点「新增」后才出现的一行：选账号下拉 + 选模块下拉 + 「确定」「取消」
   - 表格：账号 / 姓名 / 模块 / 来源 / 创建时间 / 状态 / 操作
   - 底部：全量替换提示 + 「清理无效归属（N）」按钮

**谁能用**：必须是管理员角色，或者角色里勾了「用户管理」权限，
并且该角色要有「单月签排发填报」权限。普通填报人员看不到这两个按钮。

---

## 三、逐项操作明细

### 操作 1：新增模主（给某个人加一个模块的填报权）

- 点击位置：抽屉右上角「新增」→ 出现添加行 → 选账号 → 选模块 → 点「确定」
- 账号下拉：可搜索，显示为「DT号 姓名」，已停用的账号后面会标「（已停用）」
- 模块下拉：列出系统里所有模块名（可搜索）
- 结果：
  - 表格立刻多一行，`来源` 列显示该账号的 DT 号，`创建时间` 是当前时间。
  - 该账号**立刻**获得这个模块的填报权，不需要重新登录。
  - 如果这个人原来是 0 条归属，他会从「只读汇总」变成「填报模式」。
- 失败提示：
  - 「该账号已在「X」模块」→ 这条归属已经存在，不用重复加。
  - 模块下拉里找不到的模块名，加不进去（见操作 3）。

### 操作 2：让一个现有模主同时管理多个模块（最常用）

- 点击位置：和操作 1 完全相同 —— 「新增」→ 选**同一个账号** → 选**第二个模块** → 「确定」
- 结果：
  - 这个账号在表格里变成 2 行，分别对应 2 个模块。
  - 他登录后，页面顶部会多出一个模块下拉框，可以切换模块，分别填写、分别提交。
  - 他导出「预计签排发」时，导出的内容包含他名下的全部模块。
- 要强调的一点：
  - **只能在这里手工加**。通过「导入名单」是加不上的：
    上传文件里的模块关系是靠人名去业务员表解析的，一个人解析出两个模块时，
    整条会被略过，那个人反而会丢掉全部归属。
  - 想加第三个、第四个模块，就继续重复「新增」，加一条就行。

### 操作 3：新增模块（让新模块出现在下拉里）

- 名单管理里**不能新建模块**，只能选已有的。模块下拉的名字来自这几处的合并结果：
  1. 合同完成情况的「国家-市场」映射表里的模块名
  2. 商贸数据里的模块名
  3. 固定的「改造」
  4. 已经有人填报过的模块
- 想让一个新模块出现在下拉里，两条路：
  - 由有权限的人重新上传「合同完成情况」的国家-市场映射表，把新模块带进来；
  - 或者这个模块先有人填报过一次。
- 然后回到名单管理，「新增」里就能选到它了。
- 如果新模块只在业务员表里出现、没进上面任意一处，那名单管理里是加不进去的。

### 操作 4：移除模主（把某人从某个模块拿掉）

- 点击位置：表格里找到那一行 → 操作列「移除」→ 弹窗确认「确认移除」
- 结果：
  - 只删这一行，只影响这个人 + 这个模块。
  - 他名下还有别的模块 → 那些不受影响，照旧能填。
  - 这是他唯一归属 → 他变成「只读汇总」账号：还能登录、还能看全部汇总、还能导出「预计签排发」，
    但不能再填报，也不能导出「预计发货明细」。
  - **账号不会被停用**，密码、角色、已填过的数据都不会动。
- 弹窗里的原话也提醒了：如果确实不该再由他填，建议同时去「用户管理」停用账号或换角色。

### 操作 5：换模主（把某个模块交给另一个人）

- 推荐做法（先加后删，避免中间空档）：
  1. 「新增」→ 选新模主的账号 → 选同一个模块 → 确定
  2. 找到旧模主那一行 → 「移除」→ 确认
- 结果：
  - 模块的填报权转给新人。
  - **模块下已有的草稿和提交记录不会跟着转移**：新人打开这个模块，看到的就是之前那位填的内容
    （同一份草稿，多人共用），历史提交记录里记录的提交人仍然是原来那位。
  - 所以如果旧模主还管着别的模块，别顺手把他的账号停用了。

### 操作 6：查名单 / 找问题

- 模块筛选下拉：只看某个模块的归属。
- 关键词框：按 DT号、姓名、来源（match_key）模糊搜索。
- 「只看异常」：把状态正常的藏起来，只留下「账号已停用」「账号不存在」的，用来体检。
- 「刷新」：重新拉一次名单。
- 状态列含义：
  - 正常（绿）：账号存在且启用。
  - 账号已停用（黄）：账号还在，但被停用了，本人登不进来。
  - 账号不存在（红）：名单里留着这条归属，但账号已经从平台删掉了，这条是废数据。

### 操作 7：清理无效归属

- 点击位置：抽屉底部「清理无效归属（N）」按钮，N 是上面红色行的数量。
- 只有 N 大于 0 时按钮才可点。
- 结果：把「账号不存在」的那些行一次性删掉。**不可恢复**，所以会先弹窗确认。
- 注意：它只删「账号不存在」的；「账号已停用」的不会被清理（人可能还会回来）。

## 四、和「导入名单」的区别（必须知道）

| | 名单管理（本文） | 导入名单 |
|---|---|---|
| 操作粒度 | 一条一条加/删 | 一份文件全量重建 |
| 对现有归属的影响 | 只动你操作的那一条 | **先清空全部归属再重建**，名单外的人归属会被删掉 |
| 加一个人多个模块 | 可以，重复「新增」即可 | 不行，会被整条略过，那人反而丢掉全部归属 |
| 被谁覆盖 | 下一次「导入名单」会覆盖手工结果 | 不会被手工操作"覆盖"，但本身是覆盖式操作 |
| 留痕 | 只有表格里的来源和创建时间 | 会生成一份报告，列出无账号/查不到模块/多模块被略过的人 |

一句话：**日常新增、移除、加第二个模块，都用名单管理；大规模初始化或整批换人，才用导入名单。**
导入名单是覆盖式的，点之前务必确认文件是完整名单。

## 五、常见问题速查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 加不上某模块 | 模块不在系统模块并集里 | 先让该模块进入国家-市场映射表，或先有人填报过一次 |
| 提示「该账号已在某模块」 | 归属已存在 | 不用重复加；要改模块就先移除再新增 |
| 加完还是不能填报 | 账号本身被停用，或角色没有「单月签排发填报」权限 | 去用户管理启用账号 / 调整角色权限 |
| 导入名单后手工加的多模块没了 | 导入是全量替换 | 重新手工加，或用完整名单导入 |
| 模块名单管理按钮看不到 | 当前账号不是管理员、也没有「用户管理」权限 | 找管理员开权限 |
