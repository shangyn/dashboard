## 2. 生产库预检查 SQL

在服务器上执行（只读检查，不修改数据）：

```sql
SELECT ladder_key, COUNT(1) AS active_count
FROM st_daily_shipment
WHERE is_void = 0
GROUP BY ladder_key
HAVING COUNT(1) > 1;

SELECT name, sql
FROM sqlite_master
WHERE type = 'index' AND name = 'uq_st_daily_shipment_active';

PRAGMA table_info(cc_ledger_contract);
PRAGMA table_info(st_tracking_item);
```

预期：

- 第一条查询返回 0 行。若返回重复行，先人工核对并清理，**不要直接启动带唯一索引的新版本**。
- 第二条查询在首次部署前通常为空；重启新版本后应返回部分唯一索引 SQL。
- 两条 `PRAGMA` 应在重启后分别包含 `payment_ratio`；该列允许为空，用于区分“台账未匹配”和真实的 0%。

## 3. 部署步骤

1. 停止后端服务（systemd / supervisor / 现有方式）。
2. 再次备份生产库：
   ```bash
   sqlite3 backend/instance/system.db ".backup 'backend/instance/system.db.bak-$(date +%F-%H%M)'"
   ```
3. 更新代码，确认 `backend/ship_tracking/` 存在。
4. 重新构建或上传 `frontend/dist`：
   ```bash
   cd frontend && npm install && npm run build
   ```
5. 重启后端服务。
6. 查看启动日志，应出现：
   - `[ShipTracking] 已创建有效实发唯一索引 uq_st_daily_shipment_active`（首次部署）；
   - 或没有索引创建日志，但索引已存在；
   - 不应出现 `存在重复有效实发，未创建唯一索引`。
7. 在「导入管理 → 合同台账」上传最新 `数据源/国贸合同标的台账(92).xlsx`，确认上传成功且返回的 `ship_tracking_sync.ok=true`。
8. 验证索引：
   ```sql
   SELECT name, sql FROM sqlite_master
   WHERE type = 'index' AND name = 'uq_st_daily_shipment_active';
   ```
   应返回：
   `CREATE UNIQUE INDEX uq_st_daily_shipment_active ON st_daily_shipment(ladder_key) WHERE is_void = 0`
9. 验证 10 张 `st_` 表存在：
   ```sql
   SELECT name FROM sqlite_master
   WHERE type = 'table' AND name LIKE 'st_%' ORDER BY name;
   ```
   应包含 `st_import_batch`、`st_import_issue`、`st_plan_item`、`st_tracking_item`、`st_daily_shipment`、`st_booking_record`、`st_audit_log`、`st_payment_file`、`st_payment_calc_run`、`st_payment_calc_detail`。

## 4. 生产环境冒烟（只做只读或少写）

### 4.1 管理员

- [ ] 登录后左侧出现「发货梯号明细」，打开 `/ship-tracking` 不白屏、不 404。
- [ ] 「全量明细」可加载，筛选、详情、列设置正常。
- [ ] 「回款比例」位于「订舱状态」后，显示两位小数；达到 100% 统一显示 `100.00%`，台账未匹配显示 `—`。
- [ ] 「回款比例」筛选包含 `100%`、`其他`，默认不选；两组数量合计等于总数。
- [ ] 「下载明细 Excel」成功，包含「发货明细」「发货汇总」，16 列，大区在第一列。
- [ ] 状态筛选和汇总卡片显示「未提交待发货」，不再显示「待安排」。
- [ ] 「导入管理」能看到「立即同步」「刷新状态」；不随意提交新计划文件。
- [ ] 「刷新状态」能读取最近同步时间。

### 4.2 业务填报角色

- [ ] 进入填报页，看到「待填报梯号」「我已提交 / 待发货」。
- [ ] 「保存草稿」「提交下周计划」「改期」「撤回」「手工添加梯号」按钮可见且可点击。
- [ ] 不提交真实业务数据，除非业务负责人指定测试梯号。

### 4.3 每日实发角色

- [ ] 能看到「全量明细」「每日实发」「回款计算」「导入管理」四个页签。
- [ ] 「每日实发」页签可打开，未勾选时「录入选中梯号实发」为禁用。
- [ ] 「导入管理」可打开；「立即同步」「刷新状态」可用。
- [ ] 「计划外实发」弹窗可打开、可取消。
- [ ] 不录入真实实发数据，除非业务负责人指定测试梯号。
- [ ] 切到「每日实发」后，全量页设置的隐藏状态筛选不再影响列表。

### 4.4 只读角色

- [ ] 能打开全量明细、导出、回款计算和导入管理；不出现填报/实发写入按钮。
- [ ] 导入管理能查看导入批次、异常和同步状态，页面与接口不返回 403。

### 4.5 数据同步

- [ ] 「立即同步」执行后提示「同步完成：更新 N 条（其中回款比例 X 条），未匹配台账 M 条」。
- [ ] 同步后抽查 1 个梯号：排产完工日期、整梯发货日期、回款比例变化；预计、实发、承诺、订舱未被修改。
- [ ] 台账上传或「立即同步」后，响应中的 `ship_tracking_payment_calc.started=true`；若已有计算任务则提示后等待下一轮。
- [ ] 若生产每天没有台账上传，确认是否需要增加定时同步。

### 4.6 回款计算（所有能看到主页面的角色）

- [ ] 管理员、每日实发角色、业务查看角色都能看到「回款计算」页签；页签不要求管理员权限。
- [ ] 四个文件卡片都能上传，上传成功后显示「已校验」、文件名、时间和上传人。
- [ ] 同名文件连续上传两次都能成功（每日更新常见场景）。
- [ ] 四类文件齐全后「计算回款」可点击；点击后状态从「计算中」变为「计算成功」。

- [ ] 下载明细 Excel 的回款比例与页面一致；下载审计 Excel 可打开，包含计算汇总、梯号明细、分摊明细、异常清单 4 个 sheet。
